## 1. 이 화면이 해야 하는 일

visitor mode: **Operate**(과업 완수). 사용자는 일반 환자이고, 진료 전에 자기 상태를 정리하려 한다.

```
시작 → 주 증상 1개 + 고정 3문항 → 진단 후보 3개 + 추가 질문 1 → 답변(후보 이동)
     → 추가 질문 2 → 추가 질문 3 → 현재까지 확인된 정보 정리
```

성공 기준은 "병명을 맞혔다"가 아니라 **사용자가 "내 답변 때문에 후보가 움직였다"를 스스로 읽는 것**이다.

금지 표현: "최종 진단", "AI가 진단했습니다", "1위/2위/3위". 사용 표현: "현재 확인이 필요한 진단 후보", "현재까지 확인된 정보", "추가로 확인할 정보".

## 2. 확정된 디자인 방향 — 관측 기록지

병상 발치에 걸린 임상 관측 기록지의 문법. 화면은 카드 더미가 아니라 **칸과 괘선으로 나뉜 기록면**이고,
질문 하나에 답할 때마다 기록 칸이 하나 채워지며 후보는 같은 격자 안에서 자리를 바꾼다.

이식된 규율 두 가지(챌린저에서 가져온 것):
- **레이어링**: 새 정보는 위에 얹히고 직전 값은 비쳐 남았다가 사라진다(잔상 1회).
- **격자 불변**: 변화는 같은 격자 안에서만 일어난다. 행 높이·열 위치·라벨 자리는 절대 흔들리지 않는다.

금지(리드안의 위험 방어): **선 그래프·스파크라인·게이지·주식 차트형 표현 금지.** 변화는 행 재배치 + 기호로만.

## 3. 디자인 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg` | `#F2F4F5` | 페이지 바탕(옅은 청회색) |
| `--surface` | `#FFFFFF` | 기록면 |
| `--rule` | `#D8DEE2` | 괘선·구분선 1px |
| `--border` | `#C3CBD1` | 선택 버튼 테두리 |
| `--ink` | `#101619` | 본문·병명 |
| `--ink-2` | `#5A6672` | 보조 설명·라벨 |
| `--accent` | `#0B5661` | 선택 상태, 진행 표시, 확률 막대, 기본 버튼 |
| `--error` | `#A32B1E` | 오류 상태 전용(확률 표현에 절대 사용 금지) |

- 색 전략 **Restrained**(중성 + 단일 액센트). 보라/파랑 그라데이션 없음.
- 타이포: **Pretendard** 한 가족, 숫자 `font-variant-numeric: tabular-nums`.
  display 30 / heading 22 / body 17 / label 14 / caption 13 (px), 줄간 1.5.
- 간격 스케일: 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64
- radius: 2(작은 요소) / 6(패널). 버튼 높이 48(최소 44). 포커스 링: accent 2px + offset 2px.
- 상태는 색만으로 구분하지 않는다(선택 = 테두리 굵기 + 체크 기호 + 색).

## 5. 화면별 설계

### 5-1. 시작
- 중앙 단문. 서비스명 `MedMap`, 한 줄 설명 **"증상을 한 번에 판단하지 않습니다. 확인이 필요한 정보를 하나씩 좁혀갑니다."**
- [시작하기] 하나. 하단 한 줄: "의료 행위가 아니며 진료를 대신하지 않습니다." (장문 면책 금지)
- API: `GET /health` — `engine_ready`가 false거나 실패면 버튼 비활성 + "잠시 후 다시 시도해 주세요".

### 5-2. 초기 입력 (exact-k 제약을 만족시키는 화면)
`POST /v1/session/start`는 **초기 evidence 1개 + 추가 관측 정확히 3개**(k3)만 정상 세션으로 받는다. 따라서:

```
 나이 [45]      성별 [남성] [여성]

 지금 가장 불편한 것을 하나 고르세요        ← 한국어 매핑된 binary·top-level 41개에서 선택(검색 가능)
   [기침] [열] [통증] [콧물] [숨참] [피부 병변] [부기] [두근거림] …

 세 가지만 더 확인할게요
   ① 열이 있나요?            [예] [아니요] [모름]
   ② 어딘가 통증이 있나요?    [예] [아니요] [모름]
   ③ 숨이 차나요?            [예] [아니요] [모름]

 [ 확인하고 시작 ]
```
- **고정 3문항**(승인됨): 모든 사용자에게 동일한 3개를 묻는다. UI가 임상 판단을 하는 것처럼 보이지 않고, 세션 형태가 항상 exact-k로 맞는다.
- 주 증상으로 고른 질문이 고정 3문항과 겹치면 그 항목은 3문항에서 빼고 예비 항목으로 대체(겹침 없이 항상 4개 = 1 + 3).
- "모름"은 `UNKNOWN`으로 제출된다(엔진에서 NEGATIVE와 다르게 취급). 답을 비워둘 수는 없다.
- 요청 본문에 `max_questions`·`questions_asked_in_session`을 넣지 않는다(서버가 계산·설정).

### 5-3. 진단 후보 + 추가 질문
- 질문이 주인공(22px semibold). 선택지는 카드가 아니라 48px 선택 버튼. 마지막은 항상 **"잘 모르겠어요"**.
- 질문 유형별 컨트롤: `YES_NO` 3버튼 / `SINGLE_CHOICE` 단일 선택 / `MULTI_CHOICE` 다중 선택 + [다음] / `SCALE` 0~10 눈금 버튼.
- 선택지가 12개를 넘으면 상위 12개 + "전체 보기"(검색 가능한 전체 목록 패널).
- **정보이득(bits)은 표시하지 않는다.** `?debug=1`에서만 보조 표기.
- `is_fallback: true`인 질문은 영어 원문을 그대로 쓰고 작은 회색 라벨 "영문 원문"을 붙인다(가짜 번역 금지).
- `explanation`이 `null`이므로 "왜 이 질문을 하나요?" UI는 **v1에서 노출하지 않는다**(자리만 예약, 외부 프로필을 임의 설명으로 쓰지 않는다).

### 5-4. 답변 후 변화 (핵심 차별점)
- 행 재배치 220ms(ease-out), 행 구조는 유지. `prefers-reduced-motion`이면 즉시 전환.
- 직전 값은 작은 회색으로 1회 잔상 후 사라짐. 변화 기호 `↑ / ↓ / –`(색 아님).
- 보조 문구 한 줄: "직전 답변이 반영되었습니다."
- 선 그래프·게이지 금지.

### 5-5. 현재 결과 (`stop_reason: MAX_QUESTIONS`)
제목 **"현재까지 확인된 정보"**. 한 화면에 정리:
1. 기본 정보(나이·성별) 2. 내가 답한 항목 목록(질문·답 그대로) 3. 현재 확인이 필요한 진단 후보 3개 4. 추가 확인 3/3 완료 표시
- 버튼: [진료 시 보여주기](현재 화면을 그대로 크게) · [처음부터 다시]
- 치료법·약 추천·응급도 판단 없음(엔진이 제공하지 않는다).

### 5-6. 상태·오류
| 상황 | 화면 문구 |
|---|---|
| 서버 준비 중(`engine_ready:false`, 503) | "준비 중입니다. 잠시 후 다시 시도해 주세요." + 재시도 |
| 연결 실패(네트워크) | "연결하지 못했습니다." + 재시도. 입력값은 유지 |
| 세션 형태 오류(`UNSUPPORTED_SESSION_SHAPE`) | "이 기록으로는 추가 확인을 이어갈 수 없습니다. 처음부터 다시 시작해 주세요." |
| 그 밖의 400/409 | "입력을 다시 확인해 주세요." + 해당 항목 강조 |
- **내부 코드(`MEDMAP_*`)는 화면에 절대 노출하지 않는다.** `console.error`로만 남긴다.
- 첫 요청 전 서버 기동 ~1.2초가 있으므로 시작 화면에서 `/health`를 먼저 호출한다. 턴 지연은 로컬 p95 3ms 미만이라 **스피너를 쓰지 않고**, 버튼만 중복 클릭 방지로 잠근다.

## 6. API 연결

| 화면 | 호출 | 비고 |
|---|---|---|
| 시작 | `GET /health` | `engine_ready`, `max_questions` 확인 |
| 초기 입력 → 첫 후보 | `POST /v1/session/start` | `{age, sex, model_context:"k3", initial_evidence, answers[3]}` |
| 답변 | `POST /v1/session/answer` | `{session, submission}` — 엔진이 제안한 질문에만 답할 수 있다 |
| 새로고침·복귀 | `POST /v1/session/resume` | `{session}` |

- UI는 응답의 `session`(= `medmap-session-v1`)을 **그대로 보관**하고, 확률·다음 질문·IG를 자체 상태로 저장하지 않는다.
  로컬 저장은 `sessionStorage` 1키(`medmap.session`)만 사용한다. source of truth는 언제나 서버가 돌려준 세션이다.
- 진행 표시는 응답의 `questions_asked_in_session` / `max_questions`를 쓴다(자체 카운터 금지).
- `model_context`는 `k3` 고정. `model_context_match`는 화면에 표시하지 않는다(개발용).

## 7. 접근성
- 본문 17px 이상, 대비 WCAG AA 이상(잉크 #101619 on #FFFFFF = 16:1).
- 상태를 색만으로 구분하지 않는다(선택 = 테두리+체크, 변화 = 기호).
- 모든 선택 요소 44px 이상, 키보드 Tab/Enter/Space 동작, 포커스 링 항상 보이게.
- 질문 변경 시 `aria-live="polite"`로 새 질문을 읽어준다. 후보 변화도 같은 방식으로 한 번 안내.
- `prefers-reduced-motion` 존중.

## 8. 이번 v1에서 만들지 않는 것
의사·관리자 화면, 계정/회원가입, 진료예약·병원검색, 채팅, STT(자리만 예약, 화면 노출 없음),
자연어 증상 파싱, 치료·약·응급도, "왜 이 질문인가" 설명기, 서버 측 세션 저장(DB).
