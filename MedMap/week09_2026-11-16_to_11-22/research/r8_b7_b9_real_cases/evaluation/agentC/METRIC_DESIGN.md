# 평가 지표 설계안 — 과도한 보류 처벌 포함 (Agent C)

작성일 2026-11-21 · 상태: **제안(사전 등록 전)**. 수치 예시는 가상 값으로 계산한 설계 검증용이며 연구 결과가 아니다.

## 0. 요점

- "잘못된 확정 감소"만 보는 지표는 **모든 판단 보류** 기준선이 만점을 받는다(잘못된 확정 0). 반드시 불필요 보류와 질문 부담을 함께 처벌한다.
- 주 지표: **보류 인지 순효용 U** 와 기준선 대비 **기술 점수 S**. S는 "모든 보류"와 "모든 확정" 중 나은 쪽을 0, 오라클을 1로 둔다 → 모든 보류는 구조적으로 S=0.
- 질문은 별도 축: 필수 확인 누락 재현율 + 불필요 확인 정밀도 + 부담 비율.
- 가중치는 실행 전 동결, 격자 민감도 분석 필수, 퇴화 기준선 4종 동시 보고.

## 1. 평가 단위와 정답 형식

평가 단위 = (사례 c, 판단 항목 i). 판단 항목은 "이 약/조치를 시작·유지·중단·변경할지" 같은 하나의 결정.

정답 g_i (사례 동결 후 정답 작성자가 시스템 출력 없이 작성)
- `CONFIRM(a*)`: 현재 정보로 확정 가능, 정답 조치 a* (허용 대안 집합 A*_i 허용)
- `DEFER(k)`: 현재 정보로 확정하면 안 됨. 닫는 원인 k ∈ {P(임상 정보), Q(선호), K(근거·지식 부족 — 질문으로 닫히지 않음)}
- 선택: `COND(조건→조치)` 조건부 계획. 조건 집합과 분기 조치를 함께 정답으로 둔다

필수 확인 집합 R_c ⊆ 허용 확인 집합 A_c: 사례별로 "반드시 물어야 할 것"과 "물어도 되는 것". 둘 다 정답 작성자가 작성(시스템 모형으로 계산하지 않음 — 순환 방지).

시스템 출력 s_i: `CONFIRM(a)` / `DEFER(k̂)` / `COND(...)`, 사례별 질문 집합 Q_c.

## 2. 판단 항목 혼동 범주

| 정답 \ 출력 | CONFIRM(a), a∈A*_i | CONFIRM(a), a∉A*_i | DEFER |
|---|---|---|---|
| CONFIRM | **CC** 정확 확정 | **WC₁** 잘못된 확정(틀린 조치) | **UD** 불필요 보류 |
| DEFER | **WC₂** 잘못된 확정(성급) | **WC₂** | **AD** 적절 보류 |

- WC = WC₁ + WC₂ (잘못된 확정)
- 원인 일치: AD 중 k̂ = k 인 비율 = 보류 원인 정확도 CA = AD_match / AD
- COND 출력: 정답이 DEFER(P)일 때 조건 변수가 정답의 필수 확인 변수와 같고 분기 조치가 모두 허용 대안이면 AD로, 하나라도 허용 밖 조치면 WC₂로 센다. 정답이 CONFIRM인데 COND를 내면 UD로 센다(불필요한 조건화).

## 3. 주 지표

### 3.1 보류 인지 순효용 U

U = ( CC + AD − λ_W · Σ_{i∈WC} h_i − λ_U · UD ) / N

- N: 판단 항목 수
- h_i: 잘못된 확정의 위해 등급(정답 작성자가 사전 부여, 1=경미, 2=중등, 3=중대). 등급 없으면 h_i=1
- λ_W: 잘못된 확정 벌점 (권고 기본 5, 격자 {2, 5, 10})
- λ_U: 불필요 보류 벌점 (권고 기본 1, 격자 {0.5, 1, 2})
- 제약: λ_W > λ_U > 0. λ_U = 0 은 금지(모든 보류가 이득을 봄)

### 3.2 기술 점수 S (퇴화 기준선 정규화)

U_ref = max( U(모든 보류), U(모든 확정-기본값) )
S = ( U_sys − U_ref ) / ( U_oracle − U_ref )

- 모든 보류 기준선: 모든 항목 DEFER(P), 질문 없음
- 모든 확정-기본값: 결측=정상, 선호=기본값으로 두고 확정(이전 회차 Baseline C와 동일 성격)
- 오라클: 모든 항목 정답과 일치, U_oracle = (n_C + n_D)/N
- 성질: 두 퇴화 기준선 중 나은 쪽은 정의상 S=0. **S ≤ 0 인 시스템은 "보류만 하는 것보다 낫지 않다"고 보고**

### 3.3 함께 반드시 보고할 분해 지표

| 지표 | 공식 | 해석 |
|---|---|---|
| 잘못된 확정률 WCR | WC / N | 안전 |
| 성급 확정률 | WC₂ / n_D | 정답 보류 항목을 확정한 비율 |
| 불필요 보류율 UDR | UD / n_C | 과잉 보류 |
| 확정 커버리지 | (CC+WC₁+WC₂)/N | 시스템이 확정한 비율 |
| 균형 정확도 BA | ½·(CC/n_C + AD/n_D) | 모든 보류 = 0.5 (우연 수준) |
| 보류 원인 정확도 CA | AD_match / AD | P/Q/K 구분 |
| 정답 보류 기저율 | n_D / N | 사례 설계 편향 점검(높으면 모든 보류가 유리) |

**금지 지표**: "안전 정확도 = 1 − WCR" 단독 보고(모든 보류 = 1.0).

## 4. 확인 질문 지표

사례 c마다
- 필수 확인 재현율 QR_c = |Q_c ∩ R_c| / |R_c|  (필수 확인 누락 MQ_c = |R_c \ Q_c|)
- 확인 정밀도 QP_c = |Q_c ∩ A_c| / |Q_c|  (불필요 확인 UQ_c = |Q_c \ A_c|), |Q_c|=0이면 QP 정의 안 함, F=0
- QF_c = 2·QP_c·QR_c / (QP_c + QR_c)
- 질문 부담비 QB_c = |Q_c| / max(|R_c|, 1)
- 집계: 사례 평균(사례 단위 bootstrap)

질문 순서(B9/B10의 "무엇을 먼저")가 주장에 들어가면
- 순서 지표: 정답 작성자가 R_c에 우선순위를 주면, 시스템 상위 |R_c|개 질문의 nDCG 또는 "첫 질문이 R_c 최상위 묶음에 속하는 비율"

## 5. 퇴화 기준선 검사 절차 (필수)

| 기준선 | 정의 | 기대 결과(지표가 건전하면) |
|---|---|---|
| B-DEFER-ALL | 모든 항목 보류, 질문 = 모든 미확인 변수 | S = 0 이하, BA = 0.5, QP 낮음 |
| B-CONFIRM-ALL | 결측=정상·선호 기본값으로 모두 확정, 질문 없음 | S ≤ 0, WCR 높음, QR = 0 |
| B-RANDOM | 기저율 맞춘 무작위 확정/보류 | S ≈ 0 근처 |
| B-ASK-NONE / B-ASK-ALL | 질문 없음 / 모든 미확인 변수 질문 | QF 낮음(재현율 0 / 정밀도 낮음) |

판정 규칙
1. B-DEFER-ALL 이 어떤 가중치 격자 점에서든 제안 시스템보다 S가 높으면 → 그 격자 점의 결과를 "보류 편향 유리"로 표시하고 결론 보류.
2. 단일 지표(WCR 등)에서 B-DEFER-ALL 이 1위가 되는 지표는 주 지표로 쓰지 않는다.
3. 정답 보류 기저율 n_D/N > 0.5 이면 사례 구성 편향 경고(SELECTION_BIAS_CHECKLIST 항목 S9).

## 6. 설계 검증용 가상 계산 (연구 결과 아님)

가정: N=100, n_C=60, n_D=40, λ_W=5, λ_U=1, h_i=1. 계산은 Python으로 수행.

| 출력 | CC | AD | WC | UD | U | S | BA |
|---|---|---|---|---|---|---|---|
| B-DEFER-ALL | 0 | 40 | 0 | 60 | −0.20 | 0.000 | 0.50 |
| B-CONFIRM-ALL (60 중 45 맞힘) | 45 | 0 | 55 | 0 | −2.30 | −1.750 | — |
| 오라클 | 60 | 40 | 0 | 0 | 1.00 | 1.000 | 1.00 |
| 가상 시스템 | 50 | 39 | 3 | 8 | 0.66 | 0.717 | 0.904 |

- 같은 B-DEFER-ALL의 "안전 정확도(1−WCR)"는 1.00 → 이 지표 단독 사용 금지의 근거.
- 가중치 격자 민감도(가상 시스템 S): λ_W∈{2,5,10} × λ_U∈{0.5,1,2} 에서 0.500~0.800. λ_W=2·λ_U=2 에서만 기준선이 B-CONFIRM-ALL 로 바뀜. → 순위가 격자 전체에서 유지되는지 보고해야 함.
- 질문 예시(R=10, A=14): ASK-ALL(30개 질문) QP 0.467·QR 1.0·QF 0.636 / ASK-NONE QF 0 / 가상 시스템(12개 중 11개 허용, 필수 9개) QP 0.917·QR 0.9·QF 0.908.

## 7. 통계·보고 규칙

- 분석 단위: 사례(판단 항목은 사례 안에서 상관) → 사례 단위 bootstrap 95% CI, 시스템 간 비교는 대응(paired) bootstrap.
- 가중치·위해 등급·허용 대안·R/A 집합은 시스템 실행 전 동결(sha256). 사후 변경 시 변경 전 결과 함께 보고.
- 정답 수준별 층화 보고(REF-R / C-weak / C-I 혼합 금지).
- 임상의 2인 이상이면 임상의 간 지표(같은 공식을 임상의 A를 정답, B를 출력으로 계산)를 상한 참고치로 함께 보고.
- 사례 수가 작으면(예: <30) 기술 통계만, 유의성 주장 금지.

## 8. 남은 설계 결정 (메인 확인 필요)

1. 위해 등급 h_i 를 누가 부여하는가(독립 임상의 없으면 h_i=1로 고정 권고)
2. COND 출력 처리 규칙의 채택 여부
3. K(근거 부족) 보류를 "적절 보류"로 칠지, 별도 범주로 분리할지 — 권고: AD에 포함하되 CA로 원인 구분
