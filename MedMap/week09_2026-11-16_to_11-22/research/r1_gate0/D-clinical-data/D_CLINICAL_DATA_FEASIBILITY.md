## 3. '환자 정보 부족' vs '의학 근거 부족' — 각 데이터가 무엇을 평가하게 해주나

- **환자 정보 부족**: 판단에 필요한 검사·병력이 기록되지 않음(예: UACR 미측정, 칼륨 없음, 심부전 여부 미기재). → 3값(참/거짓/미확인) + MDQ의 대상.
- **의학 근거 부족**: 정보는 다 있어도 그 환자 유형에서 이익·위험을 보여준 연구가 없음(예: eGFR<20에서 SGLT2i 신규 시작, 유지투석 환자, CKD 4기의 경구 NSAID). → 근거 의존 재평가·근거 범위 판정의 대상.

|---|---|---|---|

**ClinicalTrials.gov 사용 한계 [직접 확인 + 가설]**
- 포함/제외 기준은 **치료 적절성의 정답이 아니다**. 시험 설계자가 안전·통계 효율·규제 목적으로 정한 모집 조건일 뿐이다. 예: EMPA-KIDNEY는 유지투석·이식·1형당뇨를 제외 [직접 확인], DAPA-CKD는 eGFR 25–75, UACR 200–5000 mg/g [직접 확인]. 이 범위 밖 환자에게 SGLT2i가 "부적절하다"는 뜻이 아니라 "이 시험이 근거를 주지 않는다"는 뜻이다.
- 쓸 수 있는 용도: **"근거 적용 범위(시험 대상 범위 안/밖/판정 불가) 판정의 대리 지표"**, 근거 의존 재평가 시나리오 생성, '근거 없음'과 '금기'를 구분하는 시스템 출력 검증용 반례 생성.
- 쓸 수 없는 용도: 환자별 치료 정답, 실제 효과 크기, 지침 권고의 대체.
- 또한 openFDA는 응답 meta에 "Do not rely on openFDA to make decisions regarding medical care"를 명시 [직접 확인] → 라벨 기반 규칙도 연구용 계산 정답이지 임상 정답 아님.

## 6. 평가에 필요한 정답과 확보 방법

| 정답 종류 | 정의 | 확보 방법 | 현재 상태 |

## 8. 불가능한 실험(현재 자원 기준)

1. 임상 정답 기반 정확도(정밀도/재현율) 주장 — 환자별 적절성 정답 없음.
2. NICE·ADA SoC·NCCN 원문을 자동 규칙화해 AI에서 쓰는 실험 — 서면 허가 필요 [NICE 검색 확인, ADA 직접 확인, NCCN 검색 확인].
3. 실제 동일 환자의 임상기록 + 선호를 함께 쓰는 실험 — 그런 공개 자료 미발견. Synthea + ICPSR 결합은 "서로 다른 사람의 자료를 섞은 가상 시나리오"로만 표기해야 함.
4. 폐선암 + CKD의 바이오마커 기반 치료 선택 실험 — 규칙 원천(NCCN) 막힘, 공개 데이터에 바이오마커 없음 [Synthea 직접 확인].
5. ClinicalTrials.gov 포함 기준을 치료 적절성 정답으로 쓰는 실험 — 설계상 부적절.

## 9. 첫 질환 조합 추천

**추천: 당뇨 + CKD (조건부)** [가설 — 아래 근거 기반 판단]

근거:
1. 결정 규칙이 **정량적**(eGFR 컷오프)이라 합성 정답(A)이 모호하지 않음 [직접 확인: 합의문·openFDA 라벨].
2. **CC0 규칙 원천(openFDA 라벨)**이 있어 NICE·ADA 허가 없이도 최소 규칙 세트를 만들 수 있음 [직접 확인]. 지침 수준 규칙은 KDIGO(CC BY-NC-ND)로 내부 연구용 조건부.
3. '환자 정보 부족'이 자연스럽게 발생: UACR·칼륨·심부전 여부 미측정 → MDQ 시연에 적합 [가설: 실제 결측률은 MIMIC Demo로 확인 필요].
4. '의학 근거 부족' 경계가 명확: eGFR<20 신규 시작, 유지투석·이식(EMPA-KIDNEY 제외) [직접 확인] → CT.gov 대리 지표로 근거 범위 평가 가능.
5. 실데이터(MIMIC-IV Demo)에 크레아티닌·처방 존재 [가설: 테이블 구성은 MIMIC-IV 스키마 기준, 다운로드는 하지 않음].

약점: 선호 민감도가 CKD+OA보다 낮음, ADA SoC 사용 불가, KDIGO ND 조항. → **CKD + 골관절염을 선호 실험용 2차 시나리오**로 두는 것을 권장(Synthea OA 모듈이 CKD 무관 NSAID 처방이라 반례 생성이 쉬움 [직접 확인]. 단 OA 규칙 원천 라이선스는 [확인 필요]).

**폐선암 + CKD: 보류** — NCCN 복제 금지 [검색 확인], ESMO 미확인, 규칙 100+ 추정, 바이오마커 데이터 없음.

## 10. 개발 착수 전 해결할 문제 목록

1. NICE AI 이용 조건 **원문 직접 재확인**(이번에 403). 허가 신청 여부 결정 — 신청 전 하드룰 유지.
2. KDIGO 2024 전체본·KDIGO 2022 당뇨 지침의 라이선스 문구 확인, CC BY-NC-ND에서 "규칙화=파생물" 해석의 배포 범위 법률/기관 확인. 필요 시 KDIGO에 허가 문의.
3. ADA/KDIGO 2022 합의문에 TDM·ML 조항이 있는지 확인(SoC 2026에는 있음).
4. openFDA 라벨 규칙을 1차 규칙 원천으로 쓸 때, 제네릭/복합제 라벨 간 문구 차이 처리 기준 정의(예: 메트포르민 복합제 30–45 문구).
5. ICPSR 39508: 로그인·이용약관·코드북 변수(해악 우려 항목, 응답 척도) 직접 확인(이번에 403).
6. MIMIC-IV Demo: 다운로드 승인(사용자) 후 eGFR 계산 가능 여부·UACR 존재율 30초 실측.
7. NHANES Data User Agreement 내용과 크레아티닌·UACR·처방약 변수명 확인.
8. 전문가 확보: 최소 신장내과 1인 + 내분비 1인, 사전 정의 루브릭(규칙 충실성·임상 적절성). 없으면 논문 주장은 "합성 규칙 계산 정확성"으로 한정.
9. 대한신장학회·대한당뇨병학회 지침의 공개·재사용 조건 확인(국내 적용성 주장 시).
10. 공개 DCE/utility 데이터 탐색(이번에 특정 데이터셋 미발견) — 없으면 선호는 ICPSR 분포 + 가정 범위로만.
11. 모든 산출물에 "합성 정답(A)과 임상 정답(E)을 구분" 표기 규칙 고정.
