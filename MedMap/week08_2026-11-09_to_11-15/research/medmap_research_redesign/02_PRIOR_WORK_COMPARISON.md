## 2. 기술별 독창성 분류

분류: A 널리 존재 / B 일반적 응용 / C 특정 연구와 상당히 겹침 / D 개선 가능성 / E 새 알고리즘·실험 증명 필요.

| MedMap 기술 | 분류 | 근거 |
|---|---|---|
| 의료 용어 기반 정보 추출·개념 연결 | A | UMLS·SNOMED 매핑은 표준. R44, R17 |
| 의료 지식그래프 | A | R32, R25, R44 |
| 환자 증거그래프 | A~C | R43(환자별 그래프 + 시간). 자체 결과 Graph=Flat |
| 4값 조건 추론(AND/OR/NOT/K-of-N) | B | Belnap 4값 논리·Kleene 3값 논리의 응용(M). 임상 규칙 엔진(Arden Syntax, CQL)도 null 처리 보유(M) |
| 시간순 처리·공개 시각 관리·미래정보 차단 | C | R13, R20, R08, R50, R02. 2026년에 다수 등장 |
| 진단 에피소드 분리 | B | 에피소드 정의는 R20이 문제로 지적. 표준 해법은 미확인 |
| 중복 근거 그룹화 | D | 기록문 중복 제거는 R38 등 존재. **추론 근거의 중복 계수 방지**를 평가한 연구는 미발견 |
| 판독 정정 이력·정정 귀속 | D | 판독 수정 분석은 R39·R40·R41 존재(교육·오류 유형). **시간순 추론에서 정정 전후 판단 귀속**은 미발견 |
| 판단 변화 출처 추적 | B | 설명 가능성 일반 기능 |
| 검사 정정 가상 비교 | D | 미발견. 단 정답 없는 내부 기능 |
| 여러 가설 근거 비교 | A | 감별진단 생성기(DXplain 계열, M), R26 |
| 판단 보류 | A~B | R30, 선택적 예측 일반 |
| 연구용 규칙 비교(Shadow) 엔진 | B | 소프트웨어 공학 관행(그림자 배포) |
| 의사 진단을 입력으로 받는 재검토 | D~E | R03은 모델 자기 판단, R01·R09는 사후 판정. **의사 진단 조건부 + 시간순 + 공개 정답**을 갖춘 평가는 미발견. 단 정답 확보가 관건 |

## 3. 다섯 가지 주장에 대한 판정

| 주장 | 판정 | 근거 |
|---|---|---|
| "지식그래프를 썼으니 더 정확하다" | **반박** | 자체 실험에서 같은 지식의 평면 규칙표와 판단 100% 동일. 그래프는 저장 형식. 정확도는 지식 내용이 결정 |
| "시간순 분석을 추가했으니 독창적" | **반박** | R13·R20·R08·R50·R02가 2025~2026년에 가용 시각 문제를 직접 다룸 |
| "4값 논리라서 새 추론 기술" | **반박** | 다치 논리의 표준 응용. 성능 차이를 보인 실험 없음 |
| "여러 질병 근거를 비교하니 범용 진단 AI" | **반박** | 활성 규칙 0, 대상 3질환, 공개 SCT 연결 0. 범용성 증거 없음 |
| "정정을 추적하니 진단 오류를 찾는다" | **반박** | 정정 추적은 입력 무결성 기능. 오류 탐지 정답과 대조한 적 없음 |

## 5. 독창성에 대한 반론 (예상 심사 의견)

- "구성요소가 전부 기존 기술이다" → 사실. 기여는 과제 정의·정답·평가 프로토콜에 둘 수밖에 없음.
- "합성 사례 통과는 자기 일관성일 뿐" → 사실. 실제 정답 대조 필요.
- "진단 변경 ≠ 진단 오류" → 사실. 오류 주장 금지, "변경 사건" 과제로 한정해야 함.
- "규칙 엔진은 3질환을 넘지 못한다" → 사실. 질병 비의존 방법으로 전환 필요.
- "가용 시각 효과는 작다(F1 0.546→0.512)" → 2차 요약 기준 사실. 평균 효과가 아닌 사건 단위 영향으로 재설계 필요.
