# 개인정보 처리 원칙

## 어디서 처리하는가

| | 안드로이드 앱 | PC·브라우저(웹) |
|---|---|---|
| 음성 → 글자 | 폰 안에서만(폰 내장 오프라인 인식 + 폰 안 whisper). 음성이 폰 밖으로 나가지 않는다 | 녹음 파일을 내 PC의 FastAPI 서버로 보내 변환한다. 서버는 변환 중에만 쓰고 저장하지 않는다 |
| 증상 정리(규칙) | 앱 안 | 화면(브라우저) 안 |
| 목록 밖 AI 제안 | 앱 안(모델 파일이 있을 때) | 화면 안(모델 파일이 있을 때) |
| 확인한 기록 저장 | 그 폰의 앱 저장소(IndexedDB) | 그 브라우저의 IndexedDB |

## 원칙

- 음성은 글자로 바꾸는 동안만 사용한다. 원본 음성을 데이터베이스, 로그, Git 저장소에 저장하지 않는다.
- 녹음 중 자막, 확인 전 문장, AI가 찾은 다른 증상(제안)은 **환자가 확인하고 저장하기 전에는 기록에 넣지 않는다.**
  AI 제안은 환자가 `추가`를 누른 것만 기록에 들어간다.
- 사용자가 확인한 기록은 그 기기의 IndexedDB에만 저장하고 서버로 보내 보관하지 않는다. 다른 기기에는 자동 동기화되지 않는다.
- 사용자는 저장된 개별 기록과 기록 묶음을 화면에서 삭제할 수 있다.
- 앱은 내부 오류나 환자 문장을 운영 로그로 남기지 않는다. 파일명, 오류 종류, 처리 시간처럼 내용이 없는 정보만 기록한다.
- 개발용 테스트 음성·문장에는 실제 환자 정보나 개인식별정보를 넣지 않는다.

## 내보낸 파일 (QR · PDF · 백업)

- 진료 전 요약의 **QR**은 요약 글자를 **암호화해** 담는다(2026-11-11, AES-256-GCM, 형식은 `docs/QR_FORMAT.md`). 여는 숫자 12자리는 QR을 만들 때마다 새로 만들고 저장하지 않으며, 환자가 진료실에서 말로 전한다. QR과 번호가 함께 찍히면 보호되지 않는다.
- **PDF**(인쇄 화면에서 저장)와 **백업 파일(JSON)**에도 건강 정보가 **암호화되지 않은 채** 들어 있다. 백업 파일은 기기 안에서만 만들고 읽으며 서버로 보내지 않는다.
- 앱에서 기록을 지워도 **이미 만든 QR 사진·캡처, PDF, 백업 파일은 자동으로 지워지지 않는다.** 사용자가 직접 지워야 한다.

## 배포 전 검토할 것

- 보관 기간, 접근 권한, 삭제 방식, 사용자 동의 문구
- PDF·백업의 암호화 여부(QR은 2026-11-11부터 암호화)
